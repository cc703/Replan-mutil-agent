# 来源（provenance）
git：未传入则在 root 的所属仓库用 subprocess（git rev-parse HEAD；git status --porcelain，非空即 dirty，含未跟踪）取得；
     git 不可用则 ArtifactError，不写 "unknown"。
config：Path 读原字节，str 以 UTF-8 编码；写入 config.yaml（原字节），哈希对应原字节。
不采集环境变量、用户名、主机名、绝对路径。

# 生命周期与状态
创建即写合法的 running manifest（原子写）；创建中途失败则删除本次刚建的目录，不留无 manifest 的运行目录。
所有终态（completed/failed/partial）均关闭运行，不可再写，不可再 finish；重跑必须新 run_id。
每个会修改的方法都从磁盘读取并校验 manifest，状态不是 running 即 RunClosedError。
因此用同一 root 新建 Store/Run 对象也无法绕过。
finish 顺序：校验状态与 ended_at → 校验 outputs → 重新检查路径链 → outputs 与全部运行文件设为只读 → 原子替换 manifest 为终态 → manifest 设为只读。
任一步失败，磁盘上的 manifest 仍是 running，绝不出现假 completed。
outputs 不得指向 manifest.json、config.yaml（大小写不敏感）。

# 路径安全（paths.py）
相对路径逐段必须匹配 ^[a-z0-9][a-z0-9._-]*$，不以点结尾，不含 ~数字（8.3 别名），
不是 Windows 保留名（con、prn、aux、nul、com1-9、lpt1-9，取首个点之前的部分），
不得出现 ..、绝对路径、盘符、UNC、反斜杠、冒号（ADS）。
从 root 起逐层 lstat：任何一层是符号链接、junction 或 reparse point 即 UnsafePathError，
另用 resolve() 结果必须在 root 内作为纵深防御。创建目录时逐层检查。
链接检测放在一个可 monkeypatch 的小函数里（_is_link），用于无符号链接权限时测试其逻辑。
在 path()、write_json、finish 中都重新检查。
不使用 Python 3.12 才有的 Path.is_junction，以 3.11 的 os.lstat 与 st_file_attributes 为准。
原子写：同目录 tempfile.mkstemp → 写、flush、fsync → os.replace；失败清理临时文件，旧文件完好。
write_json：先完整序列化（ensure_ascii=False，allow_nan=False，缩进 2，末尾换行）再写盘，序列化失败不触碰旧文件。
只读：os.chmod(path, 0o444)。Windows 上这只是只读属性标志，不是目录 ACL，
须在文档与交接单披露；不声称防并发篡改（TOCTOU）或用户手工改权限。

# R1 config 与哈希（替换"config_sha256: str | None"及 provenance 中 config 一条）
Manifest.config_sha256: str，非可空，必须 fullmatch [a-f0-9]{64}（与 checker 236-239 的要求一致）。
config 参数仍为 bytes | str | Path | None：Path 读原字节，str 以 UTF-8 编码，bytes 原样；
config=None 时同样生成 config.yaml，内容为空字节，config_sha256 = sha256(b"").hexdigest()。
config.yaml 在 new_run 时写入，字节与哈希对应，不做任何换行或编码规范化。
read_manifest 必须核对：config.yaml 存在且为普通文件（非链接）、字节哈希等于 config_sha256、
manifest 与目录名绑定（run_id、kind、name、git 前缀）。任一不符即 ArtifactError。

# R2 finish 顺序（整段替换原 finish 顺序）
1 开头：删除本运行目录内本模块遗留的临时文件（前缀 .manifest-、.part-，仅普通文件）；删除失败则 ArtifactError。
2 读取磁盘 manifest，必须为 running 且绑定与 config 校验通过，否则 RunClosedError 或 ArtifactError。
3 提交前完整验证，且无任何写入：status 取值；ended_at（默认 clock，须 aware 且 ≥ started_at，规范为 UTC）；
  outputs（安全相对路径、存在、普通文件、非链接、不重复、不含 manifest.json 与 config.yaml）；
  重新检查 root 至运行目录的整条路径链，并用 os.scandir 不跟随链接地遍历运行目录，任何链接或 reparse point 即 UnsafePathError；
  构造并校验新的终态 Manifest 对象（含 outputs），序列化为字节。
4 把运行目录内除旧 manifest.json 之外的全部普通文件设为只读（含 outputs、config.yaml 与其他文件）。
  该步幂等；若中途失败，磁盘 manifest 仍是 running，已设只读的文件保持只读，合法 finish 可重试。
5 在运行目录内 tempfile.mkstemp 创建临时文件，写入新 manifest 字节，flush、fsync、关闭，并在 **临时文件上** chmod 为只读。
6 os.replace(临时文件, manifest.json)：这是唯一的发布动作，也是最后一个可能失败的操作。
7 发布成功后不再有 chmod、读文件或任何可失败 IO，直接返回第 3 步预构造的 Manifest（不再从磁盘重新读取）。
第 3 至 6 步任一失败：旧 manifest 字节不变且仍可写，清理临时文件，向上抛出原异常；清理出错不得掩盖原异常。
临时文件已是只读时，清理先 chmod 为可写再删除；删除仍失败则留待下一次 finish 第 1 步清理。
不对目录做 chmod，不声称目录 ACL；旧 manifest 在发布前保持可写，是为让 Windows 的 os.replace 能替换它。
失败的 finish 之后，已只读的输出文件不能再被 write_json 覆盖（会得到 PermissionError），这是已知并需文档化的限制；
需要改动就新建运行。
必须在本机 Python 3.11.15 上实测"以只读临时文件替换可写旧文件"可行并记入交接单；若不可行，停止上报，不自行改顺序。

# R4 强类型与绑定
GitInfo.dirty 严格 bool；commit 为 7-40 位小写十六进制 str；seeds 元素严格非负 int（拒绝 bool、float、str）；
versions 键值均为严格 str，python 项由 store 用 platform.python_version() 写入，不得靠 Pydantic 隐式转换；
调用方给出不同的 python 值则 ValueError。metadata 值仅限 str、严格 int、有限 float、bool、None；NaN 与 inf 一律拒绝。
Manifest 全部字段使用严格类型（StrictBool、StrictInt、StrictStr 或模型级 strict），并以已装 Pydantic 2.14.3 实测为准；
任何依赖 bool 是 int 子类的路径都要显式拒绝。
read_manifest：按 UTF-8 严格解码；json.loads 预检，拒绝 NaN、Infinity、-Infinity 与重复键；
再用 Manifest.model_validate_json 校验（extra=forbid）；多余字段、类型错、naive 时间、config_sha256 为 null、大写或长度不对都拒绝。
git 与 metadata 的真实性由调用方负责；自动 git 读取是实际仓库证据。文档与交接单写明。
保留名：manifest.json、config.yaml 不得被 path、write_json、outputs 指向，
包括大小写与尾随点别名（MANIFEST.JSON、manifest.json.、Config.yaml 等），由路径规则与保留名检查共同保证。
