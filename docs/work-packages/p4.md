## 范围与决定

一个实施者完成影响域、确定性邻域 0–3、稳定性目标、warm start、B2/B2s、B3 和薄仿真回调适配；一个独立审查者。P5 的诊断、松弛、Pareto、多权重候选生成及其他阶段不实现。接口可按现有模型兼容细化，保留 P2 初排行为。源事件仅处理既有 Event 联合类型；人员日历作为实例已有约束，不发明人员缺席事件。

- 输入边界：显式区分原始实例+事件与 P3 已应用事件的实例。P3 `scheduler_with_context` 回调传后者、原计划、事件及 `ValidationContext`，适配器只做影响分析和求解，不再次 apply；独立调用若支持事件应用必须复制实例，明确只应用一次。`now`、事件、计划及证据一致性不满足则拒绝，不能猜测执行状态。复用 P3 对中断重启/可抢占剩余及依赖重接，不重复产生任务；冻结 RUNNING/DONE，包括实际执行时刻、资源及合法结束变更；只有有效 `not_started` 证据可释放原本按开始时刻冻结的未开工任务。沿用 validator 对证据、RUNNING 占用绑定和截止授权的规则。
- A0 按事件类型与旧计划和新任务确定，A 按后继及同设备 W 邻接传播并记录原因；F 与 U 按证据划分。新任务和重启/残余纳入自由集，保留已完成历史。0 为 A+新任务；1 加受影响设备 [now, now+W] 任务；2 加涉及实验未开始任务；3 放开全部未开始任务；其余固定原开始、设备、人员，冻结任务不可放开。各层单调并验证 V11。
- 目标遵循 6.3：`alpha*sum(weight_i*T_i)+beta_moved*sum(moved)+beta_switched*sum(switched)+beta_shift*sum(abs(start-start0)/H)+gamma*urgent_delay`，H 为 horizon slots，H>0；比较项只对旧计划中可比较任务，新任务不计 moved/switched/shift；shift_total 报告原始槽数。CP-SAT 用有理数等比例整数化并检查溢出，不能把 shift/H 偷换为槽数。既有 HARD 和未经授权 NEGOTIABLE 截止仍由校验器严格执行；T 为 max(0,end-deadline)，无截止为 0，不能为得到非零延期放宽约束。urgent_delay：design 6.7 称紧急任务完成时间，指标表第 1150 行记为 `e_i` 与截止期之差；多任务聚合口径未明确。**G4 用户裁决待定**：root 已请求用户在本批紧急任务完成时间之和（减固定截止期不改变排序）、最晚完成时间、仅普通延期暂缓之间选择；不得自行默认或实现未裁决口径。其余 P4 范围可独立实施，urgent 目标及依赖其目标比较的验收等待裁决。
- 每层以旧计划可用变量作 hint，不能把 hint 当约束；每层按总预算递增分配并使用单调时钟记录实际时间和状态。INFEASIBLE 扩层；UNKNOWN 可按剩余预算继续但不能称无解；仅完整层 3 证明 INFEASIBLE 可报告全量无解，预算耗尽或 max_level<3 为 TIMEOUT/未证明。MODEL_INVALID 或校验不通过视为错误并报告，不发布计划。成功均以 `validate(post, candidate, base=plan0, free=Free_k, context=context)` 独立校验，校验器不引用模型。
- B2 使用相同实例/事件/now、全量自由集、相同硬约束与预算，仅延期目标；B2s 与 M 使用相同硬约束及完整目标（包括稳定性项和经用户裁决的 gamma 紧急项），仅去掉邻域扩张、直接释放全部未开始任务；B2 仅延期，不含稳定性或 gamma。B3 以 EDD 处理受影响任务，紧急任务优先插入，选兼容设备最早可行位置并传播后继右移；硬约束不满足时报告失败与违反，不能把未通过 validator 的结果作为正式计划。B3 不是 CP-SAT 方案，作为基线候选必须同样过独立校验才能返回供正式使用。
