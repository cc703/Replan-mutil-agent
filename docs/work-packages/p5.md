## 工程细化

1. 建模：每类约束钩子在 P2/P4 各自原构造中实现，默认关闭钩子时行为不变；诊断使用对应原模型构造，不复制第三套。plan0=None 时用 P2 硬约束（只接受 P2 有效输入，free=None 表示所有待排任务，显式 free 必须是全部待排任务）；有 base 时 free=None 表示全部可释放任务，仍冻结 RUNNING/DONE；显式 free 不得释放冻结任务。输入及 context 的证据必须符合既有校验规则，缺失或冲突报输入错误，不伪造证据。移除 frozen 组仅解除该组的固定时间、设备、人员及其占用绑定，任务仍受背景工期、域、release 等约束；该反事实模型仅用于诊断，不视作合法正式计划。窗口保持单独可移除，避免合并窗口丢失组语义。初排与重排目标不同，不能以目标值证明二者等价；只在适用共同域比较硬可行性。
2. 假核：全部组启用得到明确 INFEASIBLE 后，以全部组为已证明初始核；假设核可优化，但须补入所有未受假设控制的固定组，再独立证明补齐集合 INFEASIBLE 后才能使用，否则保留全部组。删除每一组均重建或正确设定所有组状态，非候选组确实禁用；INFEASIBLE 才删除，FEASIBLE 保留，UNKNOWN 保留且 minimal=False。BACKGROUND 只能在所有诊断组真正移除后的模型明确 INFEASIBLE 时返回，静态检查仅提供原因；UNKNOWN 不推断背景。MODEL_INVALID 抛内部错误。守卫仅在两模型均明确可行或不可行且相矛盾时抛 DiagnosisInconsistent；任一 UNKNOWN 则诊断 UNKNOWN。
3. 总预算：单调时钟从 API 入口计起，包括准备、建模、一致性守卫、求解、诊断、松弛及候选验证；嵌套调用传剩余预算，最多 200 次诊断求解、16 次候选求解。每次分配不超过剩余预算，不强制 0.05 秒下限；不足时不启动，返回 UNKNOWN 或已证明核 minimal=False。无法中断的建模/验证可能有墙钟开销，完成后检查期限，不再启动工作；不承诺硬实时。已验证候选在预算耗尽时仍可返回。
4. 松弛仅 free 中 NEGOTIABLE 截止；硬截止、窗口、设备、人员和先后保持。验证假设副本的截止期，原实例的同计划只允许提案涉及任务 V5；维持真实 context 及原有有效授权，不能创建或伪造 DeadlineAuthorization。假设副本与原实例分别校验；不通过不得输出。详细结果类型与 proposal 定义在新诊断模块，现有 models.py 不变；简版只返回既有 RelaxationOption。所有方案及计划仅供假设审阅，不自动采用。
5. Pareto：严格支配需至少一维严格更优；同向量但设备或人员不同均保留。仅资源分配相同且起点 L1 < max(dedupe_l1,1) 去重，优先 level、目标字典序、再按任务 ID 排序的完整 (task, device, person, start, end) canonical tuple，最后 plan.id；不依赖输入顺序。标签并列亦用 canonical tuple 再 plan.id；标签顺序最稳、最少延期、最早完成紧急、均衡。max_n 不足时按此标签顺序选不同计划，多身份合并，余量按理想点距离和 canonical tie 补足；零变化目标不贴该目标标签。候选 ID 按 base ID、level、网格序号生成并检查与 base 及本批 ID 不冲突，保持证据中 plan_id 一致。
6. weight_grid 为 1–4 个有限非负数对 (alpha, beta)，至少一个正数；alpha 替换 params.alpha，beta 同比例乘三个 beta 参数，gamma 保持 params.gamma。层级×网格最多 16 次；非法输入拒绝，不截断。候选 f 使用调用方参考 params 重算，与网格无关。任何层已有独立验证通过候选即 OK，即使其他层 UNKNOWN；无候选仅完整 level 3 已证明 INFEASIBLE 才可报 INFEASIBLE 并按剩余预算诊断；受限层级或未证明则 TIMEOUT，不能填全局冲突。诊断 UNKNOWN 时不编造冲突。事件仅应用一次。
