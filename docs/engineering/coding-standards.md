# 代码规范

状态：P0 工程约束；业务接口以导入的设计与开发规格为准。本文不冻结尚未裁决的契约变更。

## 语言与接口

- Python 目标版本 3.11；工具可使用其他已验证解释器执行治理检查，但不得因此提高业务运行版本要求。
- 模块、函数、变量用 snake_case；类用 PascalCase；常量用 UPPER_SNAKE_CASE。类型标注完整，避免用 Any 掩盖契约错误。
- 数据模型使用 Pydantic v2；语法校验与跨实体语义校验分开。边界检查 ID 唯一性、引用存在性、区间合法性与单位。
- 公共函数 docstring 说明参数、返回值、单位、前置条件、异常和是否修改输入。默认不修改输入，返回新对象。
- 不以循环导入、隐藏全局状态或动态导入绕开模块边界；核心包保持可独立导入与测试。

## 时间、数值与随机性

- 内部统一整数槽，默认一槽 5 分钟；区间左闭右开。外部 datetime 必须带时区；数据库存 UTC、业务展示 Asia/Shanghai。
- 时间轴转换必须明确向上、向下或精确对齐策略；禁止静默截断造成硬截止期或维护窗失效。
- 校验器与求解器各自实现规则，不共享同一个约束构建实现，以便发现建模错误。
- CP-SAT 整数目标权重的缩放规则需要定义与测试，不能直接把浮点偏好当作已支持的接口。
- 使用 `numpy.random.Generator` 与 PCG64，故障、工期与到达各用独立子流；禁止混用全局随机状态。
- 用户决定暂不新增单线程/性能配置档，见 ADR 0003（DEFERRED），保留原参数和公共模型。耗时、UUID 等非确定字段不应与排程本身混为同一确定性断言；测试协议的变化仍需讨论。

## 配置、错误与日志

- 可调参数外置 YAML，并校验范围与互斥条件；配置与运行 manifest 保存哈希，秘密不写入配置副本。
- DeepSeek 统一经 `src/agent/llm.py` 适配层；模型名和支持参数在使用前核实，配置化，不凭记忆写死。
- 区分输入错误、不可行、超时、外部服务失败和内部缺陷；不得把超时冒充不可行，不能用宽泛 catch 吞掉失败。
- 日志结构化 JSON Lines，含时间、级别、trace_id、工作包或运行标识。落盘前脱敏，禁止打印密钥、完整授权头与不必要的个人信息。
- 重试有次数、退避与总预算；写操作必须有幂等与版本检查，不让重试重复提交正式计划。

## 依赖与结构

- `scheduler_core`、`simulator` 不依赖 Web、数据库或大模型；应用通过适配层调用能力。
- B1 大模型基线保留原规格位置，边界冲突按 ADR 0002（DEFERRED）批注，不在 P0 实现或外移。
- Java 类、Vue 组件与 Flyway 文件遵循各框架约定，例外必须定位到路径；不得全局放宽命名检查。
- 使用锁文件与已安装版本 API；新增依赖遵循开源规范，不预装与当前阶段无关的业务库。

## 测试与审查

- 新增算法或有状态行为先写可核对的验收用例；优先黄金实例、篡改计划检查、属性测试和边界用例。
- 测试不得只重复实现；独立计算预期结果，检查错误码与反例，不只检查“无异常”。
- 临时测试文件使用 tmp_path；真实生成物使用 ArtifactStore（P1 实现后），不写源码目录。
- Python 规范工具为 ruff、mypy、pytest；是否已安装及具体版本看锁文件与依赖登记。P0 治理入口为 `python tools/check.py`。
- 修改契约时同步所有消费者及测试，保留决策记录；不通过删除断言、跳过失败或降低覆盖要求获得通过。
- 交付报告区分“执行通过”“静态审阅”“未执行”“受阻”，给真实命令及结果，不虚构检查。
