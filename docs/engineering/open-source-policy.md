# 开源工具检索与使用规范

## 选择顺序

1. 明确工作包的问题、输入输出和验收，再判断标准库是否够用。
2. 检查依赖登记与锁文件，优先复用已选且适合当前问题的依赖。
3. 只有存在实际缺口时检索新工具；至少说明候选、维护与集成成本及不采用的原因。
4. 计划/提示词由 Claude 先提供，OSS Scout 搜集证据，总设计师审查；涉及用户裁决项时先给选项和影响。

不以流行度代替兼容性验证，不为未来阶段提前安装框架。DeepSeek、PostgreSQL、uv、vis-timeline、Spring Boot 为既有技术选择，不因执行既有选择反复请求授权；变更选择或增加费用另行裁决。

## 检索记录

每次有结论的调研记录工作包、日期、查询词、候选、官方主页/文档、源码仓库、确切版本、许可证文件链接、维护状态、替代方案、选择理由及未核实事项。保存到工作包证据或依赖登记；临时页面捕获放 artifacts/tmp/，不把搜索摘要当一手证据。

API 以当前锁定、已安装版本的文档或源码为准；检查签名与参数支持，必要时先做小型可运行验证。版本号、支持矩阵、服务模型 ID、strict 等行为需要实际核实，不能从第三方说法推导为已确认事实。

## 许可证与复用

- 核实该**具体版本**的许可证文本和 NOTICE；名称、仓库默认分支与分发包许可可能需要交叉核对。
- MIT、BSD、Apache、ISC、PSF 等候选可进入常规工程审查，但仍需履行署名、NOTICE、专利或再分发要求，不能写成“无义务”。
- MPL、GPL、LGPL、AGPL、SSPL、自定义/商业条款、未声明许可或许可证兼容性疑问，向用户提交裁决请求，说明链接方式、修改范围、分发方式和替代方案；不由 Agent 作笼统法律结论。
- 不复制无来源、许可未核实的代码；获准复用后保留来源、版本/commit、许可证、修改说明，必要时保留原始头部和归属。
- 本项目 GitHub 仓库不自动等于已开源许可。LICENSE 内容与仓库可见性由用户决定，专项 Agent 不自行指定。

## 引入与更新

依赖表区分计划、已核实、已安装、锁定、待审批、退役。只有当前阶段实际采用的工具列为活动依赖；从锁文件读版本，不把“工具可运行”当作“项目锁定”。
安装来自官方源/可信包注册表并固定版本或范围及锁文件；审查新增传递依赖与安装脚本。更新属于新工作包，说明破坏性变更，跑相应检查；不顺手升级无关依赖。

Python 安全扫描可使用 pip-audit，前端可使用 npm audit；这两项为后续实际引入时的验证方法，不代表 P0 已安装、执行或没有漏洞。报告区分可利用性、影响、修复/替代措施与剩余风险，扫描通过不能替代代码审查。

## 外部服务与数据

模型服务、遥测、托管和收费 API 需单独记录数据流、预算、授权与降级策略；已授权服务只在既定目的和数据范围内使用。不向检索页面或第三方工具传递密钥、私人代码、真实实验室数据以测试功能。

## 交付

OSS Scout 输出证据与推荐，不直接安装或改锁；实施 Agent 按审查通过的工作包引入。交接列实际版本、API 验证、许可结论与来源、锁文件变化、安全检查、未解决问题及回退方法。无法核实应写“未核实”，并暂停依赖该事实的实施。
