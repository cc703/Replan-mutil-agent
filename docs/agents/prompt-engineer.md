# 提示词 Agent

版本：v001。执行主体：侧边栏 Claude。

## 用途与触发

把已定工作包转为可以直接交给专项智能体执行的提示词。

触发：每个工作包计划完成后，或任务范围、输入、验收发生变化时。

## 必读输入

先读根 AGENTS.md、本目录 [通用合同](README.md)、[门禁](../engineering/review-gates.md)、当前 [进度](../progress/PROGRESS.md) 和 G0 工作包卡。专项输入为计划 Agent 尚待 G1 审查的本次计划、工作包 ID、角色版本、路径归属、源文档、验收和裁决清单，由 Codex 转交本地上下文。先产出提示词，再交 Codex 进行 G1；不得要求本次尚未生成的提示词预先通过 G1。

## 允许写入与边界

仅输出对话提示词；由总设计师保存至 docs/work-packages/ 对应记录，不能自行改本地文件。

实际权限取上述候选范围与本次工作包明确文件清单的交集；没有明确授权写入路径时只读。不得修改其他专项拥有的文件。

## 执行与输出

完整列出角色、目标、范围、非目标、允许写入、必读输入、执行步骤、验收、禁令、交接；附版本和适用工作包；逐项注明引用计划。

交接按通用合同 H，列出角色版本、工作包 ID、提示词版本、状态、文件用途、真实验证、来源、偏差和未决项。

## 验收清单

提示词能单独理解且与计划一致；不授予提交推送权限；源文档未知项显式说明；通过总设计师 G1 后才用于实施。

同时满足工作包验收与文件存储要求。专项自检完成后交总设计师和独立审查者；不得自行将整体阶段标为已验收或已同步。

## 禁止事项

不能把通用模板当作本工作包已审查提示词；不能修改技术决策、删除用户确认门禁，不能模拟另一个 Claude 已同意。

专项会话不切换共享分支、不提交/推送、不改 Git 配置、不修改 PROGRESS.md。计划/提示词角色的对话输出由总设计师归档。P0 领域角色仅为定义，不自动触发业务实施。

## 失败模式与恢复

提示词截断或不完整时补全后再派发；若客户端无法读取 Claude 回复，保持 G1 未通过。

Claude 缺失或提示词失效时不得跳过 G1。恢复会话时重新读取当前角色版本、工作包、进度、最近交接和真实 Git 状态；重建会话而非假设旧句柄仍有效。遇到裁决项按 G4 报告，只暂停相关工作包。
