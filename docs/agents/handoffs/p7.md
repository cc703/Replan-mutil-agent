## 实现和契约

| 文件 | 用途 |
|---|---|
| `src/service/app.py`、`__main__.py`、`errors.py` | 11 个内部端点，8 MiB 边界，错误信封和追踪，Uvicorn 默认仅绑定 127.0.0.1:8000 |
| `schemas.py`、`schemas_events.py` | Pydantic 严格字段，带偏移的 ISO 时间与槽换算，按序应用 L1 事实及执行上下文要求 |
| `scheduling.py` | 现有初始/重规划 CP-SAT、影响域、独立校验、预算内冲突核与假设松弛；回滚在当前事实重验 |
| `plan_evidence.py`、`hashing.py` | 存证、当前事实独立重验、规范哈希，供设备行和叠加差异使用的上海时区视图 |
| `conversation.py` | 按实验室、会话和世界修订暂存本进程澄清，P6 提示词、工具 schema、DeepSeek 适配器、提案结构与语义验证 |
| `openapi_export.py`、`apps/contracts/` | 同步 OpenAPI、HTTP 案例和 Spring/Vue 对接合同 |
| `tests/service/` | 独立 Python 分段测试 |
| `pyproject.toml`、`uv.lock` | 直接依赖锁定并保留现有依赖版本 |

源码接口依赖 `scheduler_core.models` / `validation_context` 的类型契约、`prepare_raw` 的后置实例、`replan_candidates` 的候选、`_candidate_context` 的候选专属证据、`diff_plans` 的任务差异、`instance_to_bytes` 的实例规范字节，以及 `validate` 的独立校验。调度服务无需执行仿真推进。P6 采用 `agent.ir.parse_draft`、`agent.changes.prepare_change` 和 `agent.evidence.candidate_facts` / `agent.explain.explain`。模型仅返回经验证的提案，Spring 保存草案、L1/L2、事件和正式计划。候选解释采用 P6 已验证事实的确定性回退文本。

候选证据保存 post、父计划、free、context 和 revision。已归档证据先复验；活跃读或提交可追加待纳入事实重验，附加事实仅作当前可用性检查。手工模式基于可信静态未启动世界派生执行快照，无完整执行事实而需校验运行中任务时拒绝。上线模型路径使用待纳入事实构造 P6 上下文，涵盖设备、任务、时间轴及已知设备窗口。HTTP 预览返回核心槽单位的归一化字段，Spring 重放事实须使用原始 ISO 事件。

初始求解、重规划和回滚均复用既有核心。重规划使用核心候选池和详细诊断/松弛接口，以获取最小性与逐任务延后槽；所有确认由应用层统一执行，P6 内存 Agent 的直接提交路径未接入。初始导入仅支持静态 PENDING 世界。无进程间澄清恢复，`P7_LLM=fake` 为明确环境开关下的脚本化替身，真实 DeepSeek 在线未测。
