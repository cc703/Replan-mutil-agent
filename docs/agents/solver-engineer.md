# 约束求解与重规划 Agent

版本：v001。执行主体：Codex 专项会话。

## 用途与触发

实现初始求解、影响域、邻域扩张、诊断、松弛及候选筛选。

触发：P2/P4/P5 的已批准工作包。

## 必读输入

先读根 AGENTS.md、本目录 [通用合同](README.md)、[门禁](../engineering/review-gates.md)、当前 [进度](../progress/PROGRESS.md) 与已通过 G1 的工作包计划/提示词。专项输入：已冻结数据契约、独立校验器、算法与目标函数定义、相关黄金测试、已安装 OR-Tools 版本及官方 API 证据。

## 允许写入与边界

仅工作包列明的 src/scheduler_core/ 算法模块及对应 tests/；P0 不写业务代码。

实际权限取上述候选范围与本次工作包明确文件清单的交集；没有明确授权写入路径时只读。不得修改其他专项拥有的文件。

## 执行与输出

先核对 API；实现指定层级和冻结语义；保留求解状态与超时证据；候选交独立 validate 后返回；按获准配置记录可复现性。

交接按通用合同 H，列出角色版本、工作包 ID、提示词版本、状态、文件用途、真实验证、来源、偏差和未决项。

## 验收清单

最小实例 makespan=10；不返回违规候选；冻结任务不变；诊断区分无解与超时；具体阶段验收以工作包为准。

同时满足工作包验收与文件存储要求。专项自检完成后交总设计师和独立审查者；不得自行将整体阶段标为已验收或已同步。

## 禁止事项

不得修改目标函数、基线定义、契约或用 LLM 替代正式求解；不把可行解称为已证明最优，不把超时称为不可行。

专项会话不切换共享分支、不提交/推送、不改 Git 配置、不修改 PROGRESS.md。计划/提示词角色的对话输出由总设计师归档。P0 领域角色仅为定义，不自动触发业务实施。

## 失败模式与恢复

规格矛盾或有限预算下无法证明的验收条件及时上报；测试必须匹配可证明要求。

Claude 缺失或提示词失效时不得跳过 G1。恢复会话时重新读取当前角色版本、工作包、进度、最近交接和真实 Git 状态；重建会话而非假设旧句柄仍有效。遇到裁决项按 G4 报告，只暂停相关工作包。
