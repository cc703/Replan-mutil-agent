# ADR 0001：按 Git 视角检查布局与局部命名例外

- 状态：ACCEPTED（P0 总设计师工程审查）
- 日期：2026-11-09（Asia/Shanghai）
- 来源：开发规格 v1.1 第 2 节；Claude P0 计划；用户要求优先建立文件存储约束。
- 工作包：P0-A、P0-C

## 背景

原规格同时要求小写文件名与 AGENTS.md、README.md、Makefile 等约定文件；按磁盘根目录白名单检查还会误拒绝 .git、.venv、缓存。前端源资源与 Flyway/Java 命名也需要局部例外。

## 决定

以 tools/layout_rules.toml 为机器规则唯一源，文档镜像解释；检查 Git 跟踪和未忽略文件，不把本地被忽略的环境误判为入库文件。
根白名单精确列名；普通生成物和数据坚持小写；文档及框架约定用局部例外。任何新例外包含路径与理由，由总设计师审查，不设全局放行。

## 理由与影响

这是修复工程规则自相矛盾，不改变调度算法、数据契约或业务目标。已跟踪的 .env、缓存、artifacts 生成物仍必须报错。治理检查提前到 P0，不代表 P1 完成。
工具规则与人类文档逐条核对，并用隔离临时仓库验证合法/违规情况；不在真实源码放故意违规文件。
