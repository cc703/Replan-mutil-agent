# ADR 0003：多线程求解与确定性验收的冲突批注

- 状态：DEFERRED（用户决定暂不修改）
- 日期：2026-11-09（Asia/Shanghai）
- 裁决：用户要求按照原计划，做好批注，后续讨论；不新增 solver profile 契约。
- 来源：开发规格 v1.1 第 3、5 节；Claude P0 冲突审查。
- 最晚讨论点：P1 契约冻结及 P2 求解验收设计前。

## 背景

原规格 num_workers=8 与“同输入同种子输出完全一致”的验收存在需要验证的张力。墙钟、调度、结果排序与非确定性元数据还可能影响整对象比较。P0 没有安装/运行业务求解器，不声称已证明或消除了差异。

## 讨论选项（尚未采用）

| 选项 | 优点 | 风险/影响 |
|---|---|---|
| 保持原参数，明确比较范围与环境 | 契约保持不变 | 必须实际验证，不能承诺每次获得同一排程 |
| 区分可复现与性能运行配置 | 分别服务正确性和性能实验 | 新增契约、运行预算与评估协议，需要用户裁决 |

## 当前决定

按原规格继续，保留 num_workers 与现有字段，不新增 solver_profile、limit_kind 等字段，不把单线程或两个档位设为新默认。
manifest 先要求原规格字段，新配置字段不作为 P0 强制条件；确定性测试不能通过忽略业务差异或删除断言来假装通过。

## 后续验证

实施前查已安装 OR-Tools 版本的官方参数说明，并在同环境进行重复运行；区分解可行性、目标值、具体排程、耗时及随机 ID。再由用户决定契约/测试协议是否变更，记录正式补充 ADR。
