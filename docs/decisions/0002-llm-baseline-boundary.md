# ADR 0002：B1 大模型基线与纯核心依赖的冲突批注

- 状态：DEFERRED（用户决定暂不修改）
- 日期：2026-11-09（Asia/Shanghai）
- 裁决：用户要求按照原计划，做好批注，后续讨论；本记录不授权外移 B1。
- 来源：开发规格 v1.1 第 2、4 节；Claude P0 冲突审查。
- 最晚讨论点：B1 对应实现开始前；纯核心依赖检查涉及它时先报告冲突。

## 背景

原规格要求 scheduler_core 不依赖大模型，但将 b1_llm.py 放在 scheduler_core/baselines/，并定义需要 llm 参数的实验基线。若实现直接导入 SDK，可能破坏核心独立性。

## 讨论选项（尚未采用）

| 选项 | 优点 | 风险/影响 |
|---|---|---|
| 保持原位置，通过注入回调隔离外部调用 | 与原目录计划一致 | 必须明确核心边界及注入接口，不能据此藏入 SDK 依赖 |
| 移到 experiments/baselines/ | 运行依赖边界清晰 | 改动原规格路径和调用关系，需用户裁决 |

## 当前决定

保留原规格计划，不移动文件，不替换函数签名，不将 Claude 的外移建议当成已接受设计。P0 只保留冲突批注。
工程检查可继续保证核心不直接依赖服务 SDK；若后续实现与原计划冲突，暂停该部分并让用户讨论。不得关闭边界检查来规避问题。

## 后续验收

确认目录和接口方案后再同步规格、规则、实现和测试，并检查无大模型服务时核心仍能独立使用。P0 没有 B1 业务代码，不宣称此问题已解决。
