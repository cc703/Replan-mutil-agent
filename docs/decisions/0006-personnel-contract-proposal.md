# ADR 0006：人员资源契约提案

状态：ACCEPTED（2026-11-09 用户授权按原设计和推荐推进，工程细节委托总设计师与 Claude）。依据 `docs/source/design_v2.original.md:211`、`:214`、`:217`、`:226`、`:451`、`:758`，以及 `docs/source/codex_spec_v1.1.original.md:325`、`:334`、`:376`。规格缺人员字段但 V7 已存在。

推荐 Person、阻塞式人员日历、任务技能集合和显式人员需求、分配 person_id、实例 persons；完整字段、边界、反例与兼容规则见 [P1 契约提案](../planning/p1-contract-proposal.md)。替代为单技能和开放窗口；它们分别限制多技能或改变空日历含义。推荐空日历无阻塞，技能非空或显式要求时必须分配，已分配人员始终校验。缺分配和未知引用不能通过；V7 使用 detail，新增 subcode 须另经 G4。旧数据缺省为不启用人员需求。

影响：输入、独立校验、未来求解与生成器均受影响；缺席事件仅列影响。用户最新授权解除此前工程细节待裁决阻塞，P1-A 取得 Claude 实施计划并通过 G1 后可启动。原始设计文件不改写。

最新决定：用户原话“按原设计和推荐推进，工程细节你们决定，业务规则变化再问我”。采纳已审查人员字段、技能全部匹配、显式需求、阻塞式日历、旧JSON缺省兼容；人员只占执行区间，DONE在当前视野内保留占用与审计，冻结人员由V11维持，V8仍检查设备与开始。容量按V2/V9分流，阻塞占满容量；时间通用转换精确对齐、外部适配保守舍入。结构化求解结果为后续P2工程方向，不能提前实现求解器。RUNNING预计结束、冻结end事件证据及NEGOTIABLE授权的工程类型/持久化/API由总设计师与Claude在相关包前明确并记录，不再因字段命名等待用户；缺证据绝不判正式计划通过。以上不是业务规则变更的空白授权。B1/双profile继续延期；Hypothesis许可、费用、公开范围等独立裁决不在本次工程委托内。

G3 R1 细化：人员准备占用推荐仅执行区间，替代含准备；DONE 推荐仅当前视野内历史参与资源校验，替代完整历史；冻结人员推荐保持并由 V11 检查，V8 保留设备与开始，替代允许替换或修改 V8。各选择的影响和未裁决后果见主提案，均为 PROPOSED。
