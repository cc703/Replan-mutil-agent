## 阻塞裁决：选项、建议与影响

1. **人员技能与 V7**：v2:211-217、451、758 包含 required_skill、Person 与 person_id，而 spec:293-306、325-338 不含这些字段。选项 A 依规格 MVP 暂不支持人员并显式报告 V7 未覆盖；B 经裁决扩展契约。用户已裁决选择 B 的方向：保留 V7，先补齐人员资源契约提案；尚未批准具体字段、冻结接口或开始业务实现。影响 P1 实体、校验与测试，不能把缺失数据当通过。
2. **V2 与 capacity > 1/V9**：v2:447、455、753、760 与 spec:287-291、306 存在互斥与累积容量张力。选项 A 所有任务互斥；B 容量大于 1 时按需求累计、阻塞规则单独定义。建议用户明确 B 是否符合原意并确定阻塞与准备时间容量，影响 V2/V9、生成及未来 P2 一致性。
3. **TimeAxis 舍入**：spec:280-285 未说明槽外时间。选项 A 拒绝非对齐；B 指定按字段方向舍入。建议 A 作为可审查的保守候选，影响输入兼容及截止期安全，须用户裁决。
4. **冻结与超时长**：v2:227、453、759、761 与 spec:368-371；选项 A 冻结起点设备而允许运行中结束更新；B 整个分配冻结，事件另建实际占用。建议评审 A 与 V10 的计划/实际区分，影响重规划、占用和校验；DONE 与 RUNNING 应分别明确。
5. **NEGOTIABLE 截止期**：spec:299-301、v2:455-456。选项 A 作为加权迟延；B 经确认后才可违背。建议用户明确确认时点与目标权重，影响可行性和用户确认流程。
6. **初始求解返回 None**：spec:443-447、525-528 的接口原样待评审，None 无法区分超时与不可行。选项 A 保留接口另行返回求解诊断；B 在用户批准后扩展结果类型。建议 B 作为长期方案但先确认兼容，影响调用方和 P2；P1 不自行更改。
7. **P1 与 P2 验收**：spec:517-523 将黄金解与初始求解绑定，spec:553-554 将求解器置于 P2。选项 A P1 用手工黄金计划验证和篡改负例，P2 验证求解最优 10；B 推迟依赖求解的整个验收。建议 A，影响是 P1 不得宣称 solve 或最优性已验证。

B1 位置与求解器双 profile 已由用户延期，保留原规格；分别参见 ERRATA E-004、E-003，不在此请求批准修改。其他原文问题参见 ERRATA E-001、E-002、E-005 至 E-008，不在本稿修订原文。

## 候选工作包与依赖

- **P1-0 契约评审**：先由 Claude 计划和提示词，用户 G4 决定上述问题，形成经审查决策及可实施契约；不写业务。验收：每个阻塞都有证据和用户决策，未决项明确阻塞范围。写入清单须由本包 Claude 规划与 G1 确定。
- **P1-A 契约**：候选 `src/scheduler_core/models.py`、`axis.py`、配套测试；依赖 P1-0。验收：模型语义和时间边界覆盖、序列化与非法输入测试；不能自行扩展已批准契约。
- **P1-B 独立校验器**：候选 `src/scheduler_core/validate.py`、测试和必要测试数据；依赖 P1-A。验收：V1–V11 按用户裁决实现；spec:543 的人为重叠、先后违例检出；spec:514-523 的手工可行计划通过，不依赖求解器。无法表达的 V7 不得宣称通过。与 CP-SAT 模型独立。
- **P1-C 生成与产物**：候选 `src/scheduler_core/generate.py`、`io/artifacts.py`、`io/manifest.py`、`tools/clean_artifacts.py`、配套测试及配置；依赖 P1-A 和经批准的文件策略。验收：同种子同实例、manifest 正确、已完成运行不可覆盖/只读（spec:198-213、553）；平台只读语义须实际测试并报告限制。

P1-B 和 P1-C 在 P1-A G3 后可并行，最多三个实施会话且实际写入互斥；共享 fixtures、包初始化或配置指定单一写入者，跨包接口先对齐。候选路径并非授权清单，实际以 Claude 本包计划及 G1 为准。P2 才验证 spec:521-523 的求解最优、spec:540 的求解性质；P4 才测重规划性质（spec:541）。
